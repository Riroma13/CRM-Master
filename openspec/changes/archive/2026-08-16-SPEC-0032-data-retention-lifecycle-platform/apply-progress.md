### Bounded recovery findings and corrections

1. **Queue-provider failure — test-context correction only.** The policy PUT
   reached `JobsClientService.schedule()` and failed because the real HTTP
   `AppModule` test context did not register the `lifecycle` Bull queue, whose
   runtime token is `BullQueue_lifecycle`. Existing production `JobsModule`
   root configuration and queue semantics were not altered. The doorbell now
   imports `BullModule.registerQueue({ name: 'lifecycle' })` alongside
   `AppModule`, supplying only the disposable test context provider required by
   the real HTTP harness.
2. **Run-ledger `200` versus `404` — contract-correct expectation.** The exact
   request was `GET /api/v1/lifecycle/policies/audit-events/runs` with Host
   `lifecycle-doorbell-a.crmmaster.com`. `TenantResolveMiddleware` resolved that
   Host to Tenant A; the controller called `getPolicy`-equivalent scoped lookup
   through `PrismaService.forTenant(tenantId)` and found Tenant A's existing
   disabled `audit-events` policy seeded by the fixture. Tenant B's only run was
   not visible to the Tenant A query, so the approved contract requires `200`
   with an empty ledger (`data: []`, `pagination.total: 0`, `purgedCount: 0`).
   The Design says missing/foreign policies are masked `404`s, but this is not a
   missing policy: an existing policy with no Tenant A runs is a valid empty
   collection. The expectation was therefore updated to assert the empty
   Tenant A result, not weakened to hide a leak. The controller/service path,
   Host authority, policy lookup, and tenant filters were unchanged.
